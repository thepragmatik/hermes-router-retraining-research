Stack gains. Not guesses.

The earlier router experiment family did not clear its gates. The new thesis is to let cheap models do useful work first, then stack independent trust signals, cheap verification, selective extra compute and a curated middle tier before paying for frontier intelligence.

WHY THE PIVOT

The old router had to guess too early.

Most of the first phase tried to decide from the prompt whether a cheap model or strong model would win. The new design waits for richer evidence: the cheap answer itself, model-internal confidence, tests, tools, agreement, and workflow state.

Old bet

prompt→one router score→weak / strong

A single early decision has little information and inherits noisy labels.

New bet

cheap answer→trust evidence→escalation ladder

Every step can add independent evidence and must earn its cost.

NEXT EVIDENCE PHASE

Measure one rung at a time.

The pivot fails if it becomes another complicated architecture built on assumptions. Each component is added only after it independently moves the cost/quality frontier.

IMPORTANT RED-TEAM CAVEATS

No new silver bullet.

Signals are task-dependent

Internal confidence can help on some domains and fail on others. Agreement can be confidently wrong. More models can duplicate each other's failures.

Single-draw labels may be noisy

Recent work suggests part of the apparent routing oracle can come from stochastic one-off generations. That makes adaptive resampling worth testing before another classifier search. Read the adversarial notes →

THE STRATEGIC IDEA

Make expensive intelligence the last resort, not the default.

Cheap work→Trust evidence→Cheap repair→Mid-tier→Frontier only if unresolved↻

The durable capability is not a router checkpoint. It is a system that can cheaply determine when work is trustworthy, add only the minimum extra capability needed, and learn from recurring escalations.
